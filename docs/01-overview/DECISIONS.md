# Skill Registry - 已确认的设计决策

> 记录所有关键设计决策及其理由

---

## 决策 1：多目标同步

**状态**: ✅ 已确认

**决策内容**：
- 一个 Skill 可以同时同步到多个 Target
- 项目定义的 Targets 决定同步目标
- 同步时将所有 Skills 分发到所有 Targets

**理由**：
- 支持多智能体协作场景
- 一个项目可能同时使用多个 AI Agent
- 需要保证所有智能体使用相同的 Skill 集合

**实现方式**：
```yaml
# 项目配置
targets:
  claude-code: {}
  cursor: {}
  codex: {}

skills:
  - drawio
  - pua
```

**同步行为**：
- 每个 Skill 都分发到所有 Targets
- 所有智能体使用相同的 Skills

## 决策 2：全局预定义 Targets

**状态**: ✅ 已确认

**决策内容**：
- 全局配置预定义所有可用的智能体
- 项目自动继承全局预定义
- 项目可以选择使用哪些 Targets
- 项目可以自定义覆盖

**理由**：
- 新智能体出现时，只需在全局添加一次
- 所有项目立即可用
- 避免每个项目重复配置
- 统一管理智能体路径规范

**实现方式**：
```yaml
# global.yaml
defaults:
  targets:
    claude-code:
      path: .claude/skills
    cursor:
      path: .cursor/rules

settings:
  default_target: claude-code
```

**继承规则**：
- 项目未定义 targets → 使用 default_target
- 项目定义 targets → 只使用声明的

---

## 决策 3：项目级 Skill 集合管理

**状态**: ✅ 已确认

**决策内容**：
- 项目中所有智能体使用相同的 Skill 集合
- Skills 只需声明，无需指定 targets
- 添加 Skill = 声明需求
- 拉取操作 = 分发到所有 Targets

**理由**：
- 保证所有智能体使用一致的 Skills
- 简化配置，避免每个 Skill 单独配置
- 符合项目级管理理念

**实现方式**：
```yaml
# 项目配置
skills:
  - drawio
  - pua
  - theme-factory
```

**关键点**：
- ❌ 不支持每个 Skill 单独指定 targets
- ✅ Skills 只是声明，无 targets 字段
- ✅ 同步时全量分发

---

## 决策 4：单向增量拉取

**状态**: ✅ 已确认

**决策内容**：
- 使用 `pull` 命令（不是 `sync`）
- 只做增量，不删除已存在的链接
- 移除 Skill 只更新配置，不删除文件

**理由**：
- 保护智能体动态创建的 Skills
- 避免误删用户文件
- 配置和实际分离更安全
- 防止配置错误导致数据丢失

**实现方式**：
```bash
# 拉取（只添加）
skill-registry project pull

# 移除（只更新配置）
skill-registry project remove drawio
# → 配置中移除，链接保留
```

**安全设计**：
- ✅ pull 只添加新链接
- ✅ 不删除配置中移除的链接
- ✅ 保护动态创建的文件

## 决策 5：Skill 格式标准

**状态**: ✅ 已确认

**决策内容**：
- 完全支持 Claude Code 的 Skill 标准（SKILL.md）
- 遵循业界通用的 Agent Skills 开放标准
- 不做个性化格式转换

**理由**：
- 遵循行业标准
- 兼容性好
- 减少维护负担

**实现方式**：
- 同步时直接链接 SKILL.md 文件
- 不做任何格式转换
- 如果某个智能体需要不同格式，用户需自行准备

**不支持**：
- ❌ 格式转换（如 .mdc）
- ❌ 个性化格式适配

---

## 决策 6：注册机制

**状态**: ✅ 已确认

**决策内容**：
- **Git Skill**: 克隆到中心仓库
- **本地 Skill**: 复制到中心仓库
- 记录源路径和快照信息

**理由**：
- 统一管理所有 Skills
- 支持版本控制
- 支持更新检测

**实现方式**：
```
~/.skill-registry/skills/
├── git-abc123/drawio/    # Git 来源
└── local-xyz789/pua/      # 本地来源
```

**更新机制**：
- Phase 1: 手动全量更新
- Phase 2: 智能检测 + 增量更新

## 决策 7：链接策略

**状态**: ✅ 已确认

**决策内容**：
- 项目中只创建单层软链接
- 链接指向中心仓库的缓存目录

**理由**：
- 避免多层软链接混乱
- 清晰可靠
- 便于管理

**实现方式**：
```
项目：   .claude/skills/drawio
         ↓ 软链接
中心仓库：~/.skill-registry/skills/git-abc/drawio/
         (实际文件)
```

## 决策 8：家目录作为项目

**状态**: ✅ 已确认

**决策内容**：
- 家目录 `~` 也是一个项目
- 与一般项目使用完全相同的管理机制
- 唯一区别：项目根路径不同

**理由**：
- 统一管理全局 Skills
- 简化设计，无需特殊处理
- 使用相同的工作流程

**实现方式**：
```yaml
# ~/.skill-registry/config.yaml
targets:
  claude-code-home: {}

skills:
  - pua
  - handoff
```

## 决策 9：Group 的定位

**状态**: ✅ 已确认

**决策内容**：
- Group 是全局的批量添加工具
- 只存在于 global.yaml
- 不存储在项目配置中
- 作用：快速添加一组相关 Skills

**理由**：
- Group 是松散的概念
- 最终落地的粒度还是 Skill
- 避免配置复杂化

**实现方式**：
```yaml
# global.yaml
groups:
  web-dev:
    skills: [drawio, theme-factory, code-review]
```

**使用**：
```bash
# 应用 Group → 添加多个 Skills
skill-registry project group add web-dev
```

## 决策 10：项目配置字段

**状态**: ✅ 已确认

**决策内容**：
- 移除 `project` 字段（无意义）
- 移除 `skills[].targets` 字段（不支持）
- 移除 `default_targets` 设置（使用全局）

**理由**：
- 项目配置文件已在项目目录，无需声明名称
- Skills 统一分发，无需单独指定 targets
- 使用全局预定义，简化配置

**最终配置格式**：
```yaml
# .skill-registry/config.yaml

# 项目 Targets（可选）
targets:
  claude-code: {}
  cursor: {}

# 项目 Skills
skills:
  - drawio
  - pua
```

## 决策总结

### 核心理念

1. **全局预定义，项目继承**
   - 全局定义所有可用智能体
   - 项目自动继承，灵活定制

2. **项目级 Skill 管理**
   - 所有智能体使用相同 Skills
   - Skills 统一分发

3. **单向增量拉取**
   - 只添加，不删除
   - 保护动态创建的文件

4. **标准化**
   - 遵循行业标准
   - 不做格式转换

## 决策 10：无数据库

**状态**: ✅ 已确认

**决策内容**：
- 完全基于文件系统存储
- 不使用数据库
- 所有信息从文件获取

**理由**：
- Skills 数量有限（通常几十个）
- 文件系统性能足够
- 透明可理解
- 减少依赖

**实现方式**：
- Skill 信息：SKILL.md frontmatter
- Git 信息：`.git/` 目录
- 时间信息：文件系统
- Groups：global.yaml

---

## 决策 11：无额外元数据文件

**状态**: ✅ 已确认

**决策内容**：
- 不创建 `.skill-meta.yaml`
- 不创建索引文件
- 所有信息从现有资源获取

**理由**：
- 元数据可从其他地方获取
- 避免同步问题
- 减少维护负担

**信息来源**：
- **Skill 信息**：SKILL.md frontmatter
- **Git 信息**：`.git/` 目录（git remote, git log）
- **时间信息**：文件系统

---

## 决策 12：扁平目录结构

**状态**: ✅ 已确认

**决策内容**：
- Skills 目录扁平结构
- 直接使用 Skill 名称
- 名称必须唯一

**理由**：
- 路径简洁
- 易于理解
- 避免复杂层级

**实现方式**：
```
skills/
├── drawio/
├── my-skill/
└── pua/
```

**规则**：
- Skill 名称唯一
- 冲突时用 `--name` 或 `--force`

---

## 决策 13：注册机制简化

**状态**: ✅ 已确认

**决策内容**：
- `skill add` 只做复制/克隆
- 不替换软链接
- 不创建额外文件

**理由**：
- 保持简单
- 不影响原位置
- 用户可继续原位置开发

**实现**：
```bash
skill-registry skill add <source>
# → 复制到中央仓库
# → 完成
```
